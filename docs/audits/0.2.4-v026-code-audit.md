# Skyblock Multi 0.2.4-v026 code audit

## Scope

- Core initialization and event/command registration.
- Nexus/OpenPAC ownership boundaries.
- Built-in and data-driven Infernal Trial execution.
- Tree addon schema and starter planting stock.
- Mod Menu/configuration compatibility paths.
- Datapack JSON, locale parity and duplicate source/resource content.

## Confirmed cleanup

- Removed the unreachable OpenPAC 5x5 reservation, 3x3 assignment and legacy
  initial-island claim implementations. No active source or datapack referenced
  these methods and their feature switch was permanently false.
- Preserved OpenPAC's permanent Nexus Server Claim and optional party discovery.
- Removed the duplicated Nexus interaction-policy synchronization pass; the claim
  preparation path already applies the same policy.
- Removed an unused Infernal data snapshot retained by each active dynamic trial.
- Removed redundant participant clearing and a one-use broadcast wrapper from the
  Infernal reward/voting state.

## Correctness fixes found during audit

- Data-driven trials now use their declared `health_per_extra_player`; the default
  is 10% per additional participant and champions receive 1.75 times that increase.
- Island-difficulty health and damage multipliers are now actually applied in
  addition to mob and participant multipliers.
- Scaling uses the participants present for the phase and observes the declared
  maximum participant count.

## Verification

- All 13 locales have parity with `en_us` (533 keys each).
- JSON resources parse successfully; the empty blockstate variant key is valid
  Minecraft JSON and was checked using hashtable-aware parsing.
- No byte-identical Java or mcfunction files were found.
- No source references remain to the retired OpenPAC island-claim helpers.
- `git diff --check` completed without whitespace errors.
- Gradle `build` completed successfully on 2026-09-11, including compilation and
  the Infernal data API, island-ring, logical-region, party-provider and tree
  configuration verification tasks.
- A preliminary `clean` could not remove Gradle's active `hsperfdata` folders on
  Windows; this was an environment file-lock issue, not a source or test failure.

## Intentionally retained compatibility code

Legacy tree IDs/config keys and legacy 8/16/24 island geometry remain active
migration and world-compatibility contracts. Public configuration overloads were
also retained because external callers may compile against them. Removing these
would be a compatibility change rather than safe cleanup.
